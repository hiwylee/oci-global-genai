Case C · 벡터 스토어 / File Search

Enterprise AI Agents · 리전 리소스

Files · Vector stores · file_search

Files는 업로드한 문서, Vector store는 문서를 청크로 나눠 임베딩한 검색 인덱스, file_search는 Responses API가 답변 전에 벡터 스토어를 검색하도록 하는 툴입니다. 모두 OCI Generative AI의 Enterprise AI Agents 기능입니다.

이 리소스들은 엔드포인트 리전에 생성되는 리전 리소스이며 라우팅 프로파일로 다른 리전에 넘겨지지 않습니다. Seoul은 지원하지 않습니다: 벡터 스토어 생성은 403 {"code":"NotAllowed","message":"GenerativeAiVectorStore is not supported"}, Files 업로드는 404. 그래서 이 데모는 Chicago(us-chicago-1)에 만듭니다.

또한 라우팅 프로파일 OCID를 model로 지정하고 tools를 함께 쓰면 400(entity not found)이 나므로, Case C는 Chicago 엔드포인트에서 xai.grok-4.3 모델 이름을 직접 호출합니다.

Seoul을 선택하면 실제 403/404 오류를 그대로 볼 수 있습니다. 모델: —

1. 벡터 스토어 생성

2. 벡터 스토어 목록

3. 파일 업로드 및 연결

4. 검색

5. 질문 (Responses + file_search)

Case D · OCI SDK 네이티브 API (embed / rerank / chat)

oci.generative_ai_inference · 사용자 principal

모델 이름 직접 호출 vs Seoul 라우팅 프로파일 경유

같은 기능을 OpenAI 호환 API 대신 OCI Python SDK(GenerativeAiInferenceClient)로 호출합니다. API 키가 아니라 ~/.oci/config 프로파일의 OCI 요청 서명(사용자 principal)을 쓰며, serving_mode=OnDemandServingMode(model_id)의 model_id에는 모델 이름이나 라우팅 프로파일 OCID를 넣을 수 있습니다.

  • embed / rerank는 라우팅 프로파일로 라우팅되지 않습니다. Seoul에서는 모델 이름 직접 호출만 가능하며 리전 제약으로 실패합니다.
  • Cohere Command 계열(cohere.command-a-03-2025)은 api_format=COHERE(CohereChatRequest)가 필요합니다. GENERIC으로 보내면 실패합니다.
  • google.gemini-2.5-pro는 현재 Chicago에서도 Google 측 NOT_FOUND를 반환합니다.
  • Seoul에서 Gemini를 모델 이름으로 직접 호출하면 Google asia-northeast3로 전달되어 실패합니다.
